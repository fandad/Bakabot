# Bakabot v2.9.0

> ⚠️ **开发者必读：本仓库有强制约束，见 [AGENTS.md](./AGENTS.md)。**
> 最重要的一条：**禁止按进程镜像名杀 `java` / `node`** —— 用户的 Minecraft 客户端
> 进程名就是 `java.exe`，按名字杀会静默杀掉用户正在玩的游戏（无任何日志、退出码 -1）。
> 任何"重启 / 清理 / 构建前先杀进程"都必须按命令行特征或精确 PID，详见 AGENTS.md 规则 1。

> AI 制作声明：本项目采用生成式 AI 参与协议设计、编码、文档编写与测试；AI 生成或修改的内容均由项目维护者审阅、验证并承担最终维护责任。

声明：本项目的核心底层交互基于优秀的开源框架 mineflayer 开发，特此致谢！本项目主要致力于提供开箱即用的可视化 UI 界面，降低新手使用门槛。

> **本项目由 [ARCbot](https://github.com/FENTAIIII/ARCbot) 改版而来**，在保留原有功能的基础上进行了重命名与大量功能增强。原 ARCbot 官网（bot.myarc.icu）已关闭，本仓库为当前维护版本。

欢迎使用 Bakabot！本指南将手把手教你如何通过控制面板快速配置并召唤你的专属 AI 机器人。

## 📦 更新日志

### v2.9.0

* **新增「关键词连听」**：以前在「主人+关键词」「任何人说关键词」这类模式下，**每一条**消息都必须带关键词。现在可以在编辑实例里打开连听，并设置条数与超时——触发一次之后，**同一个人的接下来几条消息不用再说关键词**也会被回应。
  * 只粘**最近一次**通过触发判定的人：别人正常触发会直接截断替换；无关的人说话既不会打断、也不会扣掉你的次数。
  * 超时可自己开关，默认 **60 秒**；开启时是滑动计时，每收到一条被连听的消息就重新计时。
  * 默认**关闭**，不改变现有行为；只对关键词类触发模式生效（只听主人模式没有关键词概念，因此不生效）。
* **修复「装了 TrChat 等聊天插件的服务器收不到消息」**：这类插件会把玩家聊天包装成**系统消息**发送（TrChat 2.x 在现代版本用 `sendSystemMessage`）。而底层 mineflayer 的聊天事件其实是**用一条正则去匹配渲染后的字符串**产生的，格式稍有变化就会匹配失败（消息全丢）或把前缀里的词当成说话人（主人判定失败）。
  * 现在会自动识别：能正常解析的服务器**完全不受影响**；解析不了或认错人的，改用「消息组件里的点击私聊信息 + 在线玩家名单」重新确定说话人再处理。
  * 同一条消息只会处理一次，不会因为两套识别都命中而重复回应。

### v2.8.3

* **修复「QQ 内容漏进服务器聊天」**：以前偶尔会有 QQ 来的对话被发到 Minecraft 服务器公屏上。原因是**机器人回复走哪条通道，是在"发送那一刻"才去读一个全局标志决定的**，而 QQ 的回复要等大模型想几秒才生成——这期间只要刚好有**别的玩家在公屏说话、或给机器人发私信**，这个标志就被切成了"游戏通道"，于是 QQ 的回复落地时就跑到服务器里去了。这也解释了为什么是"偶尔"发生、很难复现。
  * 现在改成：每条 QQ 指令在**收到的瞬间就记下自己该走哪条通道**，回复生成后按这个记录发送，不再受中途事件影响。
  * 顺带修正了一处判断：机器人正在思考时，那条打断它的游戏内消息其实**根本不会被执行**，以前却照样把通道切走了——现在只有"确实会被处理"的游戏消息才会切通道。
* **修复「机器人有时完全不思考」**：当某个 QQ 号在「QQ 白名单」里绑定的游戏名**和机器人自己的游戏名一样**时，这个 QQ 号发什么指令机器人都毫无反应（不思考、也没有任何报错）。原因是基础包有一句"忽略机器人自己发的消息"的判断，把这条 QQ 指令当成机器人自己说的话丢掉了。
  * 现在**绑成什么名字都能用**了：QQ 转达的指令不再复用绑定名去当"说话人"，不受撞名影响。
  * 顺带纠正了由此暴露的一个老问题：以前"主人名单"被压缩成只剩第一个主人之后才去做判断，导致**除第一位以外的其他主人可能被误拒**——现在名单在压缩前就完整保留。
  * 机器人自己在游戏里说的话**仍然会被正确忽略**，不会误触发。
* **主人判定改为精确匹配**：以前判断"说话的人是不是主人"用的是**子串比较**，会误判——例如名单里第一个主人叫 `Cold_` 时，另一个叫 `Cold_Fan` 的玩家也会被当成主人；名单里有 `w0nderfu_11` 时，缩写 `0nderfu` 也会被当成主人。现在改为按逗号名单**精确匹配**（忽略大小写与首尾空格），对正常玩家没有影响，只是不再认错人。
* **修复「命令提示词的回执串台」**：在 QQ 里说过话之后，如果紧接着**在游戏里**用「命令提示词」（固定关键词立即回应的那种），回执会被发到 QQ 而不是游戏里；在游戏里再随便说一句，之后才恢复正常。
  * 原因和上面"漏进服务器聊天"是同一类问题：判断"这条指令是从哪儿来的"时读的是一个**会被随时改写的全局标志**。QQ 会话结束后这个标志不会马上归位，要等"下一条会被处理的游戏消息"才清掉——所以 QQ 说完话之后游戏里的**第一条**命令提示词就被认成了 QQ 来源。
  * 现在改为按**本次指令的来源**判定（谁触发的就回给谁），不再受残留状态影响。
* **基础包 `plugins/` 技能插件更新**：修好了「切换空手」在**快捷栏 9 格全满**时必然失败的问题（报 `inv.moveSlotItem is not a function`——该 API 实际挂在 `bot` 上、且是异步的），并统一了三个插件的播报门禁（QQ 通道下的动作播报不再被静默吞掉）。
* **补丁机制加了语法自检**：启动器每次给实例写入补丁后会自动做一次 `node --check`，一旦把脚本改坏**当场报警**，不会再出现"装完才发现机器人起不来"的情况。

### v2.8.2

* ⚠️ **更正：本条目下的「修复任务栏图标不显示/发虚」实际已撤回，未包含在 v2.8.2 里。** 该改动因会让 exe 体积明显变大而被回退（`icon.ico` 恢复为原始单档 128×128），**任务栏图标问题至今未解决**。下面这段仅作历史记录保留，请勿据此认为已修复。
* ~~**修复任务栏图标不显示/发虚**~~（已撤回）：以前**只有主窗口**的任务栏图标是空的（显示成系统默认的空白文档图标），而编辑实例等对话框看起来正常——因为那些对话框是无边框窗口、根本不进任务栏。原因是主窗口从未设置过窗口图标（`Window.Icon`），WPF 在未设置时会使用自己的默认图标，**不会**去用 exe 内嵌的图标。现已显式设置，并把图标文件从**单张 128×128** 补全为 **10 档标准尺寸**（16/20/24/32/40/48/64/96/128/256）。这一点在高 DPI 屏幕上尤其明显：以前系统只能把 128px 硬缩到 24px，糊得厉害。
* **「主人关键词」模式修复**：`owner_keyword` 模式此前**实际等同于 hybrid**（主人说什么都回应、关键词完全不起作用），原因是判定逻辑那一处注入没生效、只注入了模式白名单。现已修正为正确的语义：**每一条消息都必须自带关键词**——主人不带关键词不触发、他人带关键词也不触发。
* **更新提示改为查询 GitHub Releases**：以前启动时会请求 `http://localhost:3000/update`（早期版本遗留的自建更新服务地址），在普通用户机器上**没有任何服务监听**，于是每次启动都白等 5 秒超时、且永远不可能提示更新。现在改为查询本仓库的 GitHub Releases 最新正式版；发现新版本会弹出提示窗，点「去下载」打开下载页。
  * 同时移除了旧的"自动下载并替换自身 exe"逻辑——本项目的发布包是 zip（含启动器 + 基础包），那个自替换流程对 zip 无意义且会破坏安装，现改为提示后由你自行下载覆盖。
  * 勾选「跳过此版本」后该版本不再提醒。

### v2.8.1

* **修复"服务器升级到 26.2 后机器人进服十几秒就死"**：服务器版本换到 26.2 后，ViaProxy 转发过来的粒子包用 1.21.4 的协议解析器读不了，会在十几秒内产生**上千次解析错误**并把日志刷到几 MB，机器人随即猝死（退出码 `-1`）。现在这类解析错误**只静默跳过、不再刷屏**，机器人能正常进服并持续工作（实测：错误数 2926 → **0**，日志 2.9 MB → 15 KB）。
  * 说明：粒子是纯视觉效果，跳过它不影响机器人行为。协议帧是按长度切分的，坏包不会影响后续包。
  * 另外加了一层兜底：万一真出现解析错位，会限流记录而**不会让机器人猝死**。
* **任务连贯性大幅增强**：修复"分步做都正常、连起来做就出错"的问题。此前的逻辑是**每个步骤自己说自己成功**，没人校验产物是否真的可用，于是错误一路传到下一步。
  * **合成产出校验**：合成后确认产物**真的进了背包**，没进就如实报失败（而不是谎报成功，让下一步扑空）。
  * **丢弃生效校验**：丢弃后确认背包数量**真的减少了**，没减少就报失败。
  * **修复同一工作台被开两次窗口**：此前 `CraftItem` 自己开一次工作台、`mineflayer` 内部又开一次，会让合成在客户端成功、却被服务器**回滚**——这正是"报成功但东西没了"的根源。
  * **步骤间验真**：每步完成后检查下一步的前置条件是否真的满足，不满足会明确告诉你"上一步没真正交付"。
  * **修复先决条件检查一直失效**：AI 输出的是 `has_items`，而校验代码只认 `items`，导致前置条件检查从未生效——现已两种写法都支持。
* **调试更方便**：调试模式下会在合成/丢弃等关键节点打印**真实背包 + 手持物品 + 当前窗口**，一眼看出"东西到底去哪了"。

### v2.8.0

* **AI 配置界面化（内置 30+ 家服务商预设）**：创建/编辑实例的「AI 配置」不再只能手填文本框——现在先选**服务商**，API 地址与模型名自动填好，你只要填 API Key。内置 30 多家，按「国内官方 / 国际官方 / 聚合中转 / 本地部署」分组，涵盖 Agnes AI、DeepSeek、火山方舟、Kimi、智谱 GLM、阿里百炼、MiniMax、硅基流动、阶跃星辰、百度千帆、腾讯混元、讯飞星火、百川、商汤、魔搭、OpenAI、Gemini、Groq、Mistral、xAI、OpenRouter、NVIDIA、DMXAPI、AiHubMix、Ollama、LM Studio、vLLM 等。
  * **一键拉取模型**：填好地址与 Key 后点「拉取模型」，自动向服务商查询可用模型列表并列出（对话模型排在最前，embedding / 语音 / 图像类靠后），不用再手抄模型 ID。
  * **「去申请 Key」按钮**：直接打开该服务商的注册页面。
  * **服务商会被记住**：编辑已有实例时按它**已保存的 API 地址**自动认出对应服务商；新建实例时默认选你**上次用过**的那家。
  * 换服务商只替换地址与模型名，**不会清空你已填的 API Key**。
* **容器取物更可靠**：修复"有时候认不出容器里的东西"。原来打开容器只读一次内容，读到空就立刻换下一个，没有任何等待或重试；现在读到空会稍等再重读（最多 3 次），并在调试模式下打印容器实况，便于定位问题。
* **按附魔取附魔书（如"经验修补"）**：修复"让它取经验修补附魔书却看不到"。此前只按物品名匹配，而**所有附魔书的名字都叫 `enchanted_book`**，区别全在附魔数据里，因此无法区分是哪一本；现在支持直接写附魔名（`mending` / `经验修补` / `锋利5` / `enchanted_book mending`），会按物品**实际附魔**匹配并取出正确的那一本。
  * 说明：Minecraft 1.20.5 起附魔数据由 NBT 迁移到**物品组件**，本版已按新结构读取；若服务器使用了**数据包自定义附魔**，其附魔编号可能不在客户端标准编号内，这种情况识别不了。
* **触发模式新增第 4 种「主人关键词」（`owner_keyword`）**：在原有 hybrid / owner_only / keyword_only 之外，新增"**主人 + 关键词**"叠加模式——只有主人说了含关键词的消息才触发；他人说关键词不触发，主人不带关键词也不触发。适合"只想被主人用暗号唤起"的场景。
  * 注意：该模式**必须填写「触发关键词」**，否则永远不会触发。需要它停下时，主人说"停止/取消"即可。
* **正版账号可选择（修复"多账号只能永远用第一个"）**：以前通过 ViaProxy 进入正版验证服务器时，启动器写死使用 ViaProxy 里配置的**第一个**微软账号；配置了多个账号时，无论怎么改实例里的用户名，实际登录的都是第一个账号。现在「设置 → 协议代理 → 正版账号」新增账号下拉框，会列出你配置过的所有账号（显示为 `1: 账号名`），选中哪个就用哪个登录；状态栏也会明确写出"进入正版验证服时使用第 N 个：账号名"。
  * 同时明确一件事：实例里填的**机器人用户名不参与正版验证**（机器人以离线身份连接本地代理，真正的正版验证由 ViaProxy 用所选账号完成），所以改它不会切换登录身份——要用哪个账号请在设置里选。
  * 切换账号后需要**停止并重新启动实例**才生效。
* **ViaProxy 下载真正拿到最新版（修复"下载最新版却给旧版"）**：以前下载兜底地址写死了某个旧版本，且 GitHub 接口一旦失败就静默退回该旧版；同时文件已存在时不会重新下载，导致长期停留在旧版。现在下载改为**始终覆盖重下**（旧文件被占用时会明确提示先停止实例），并按"GitHub 最新发布接口 → latest 免接口重定向 → 内置兜底版本"三级方式解析最新版，自动优先选择正式版而非 `+java8` 专版。
* **ViaProxy 版本可见可更新**：「设置 → 协议代理」现在显示本地已装版本，并在 GitHub 上有更新版本时提示"有新版 vX.Y.Z"，下载按钮文案同步变为「更新到 vX.Y.Z」，一眼就能看出该不该更新。

### v2.7.1

* **NapCat DLL 完整性自检**：QQ 功能页在「机器人 QQ 号」与「NapCat 协议端」之间新增手动「检验完整性」入口，点击后先弹窗确认，再主动检查 NapCat 依赖的 crypto.dll / ssl.dll 是否就位，并把完整检验结果展示在状态栏。若发现缺失，会按启动兜底逻辑自动补齐：先递归查找 NapCat 包内是否自带，找不到再从本机 QQ 安装目录复制（只复制、不移动、不覆盖已有文件），解决官方包漏打包导致的启动即报错问题。

### v2.7.0

* **QQ 登录状态可视化（QQ 排查结果落地）**：排查确认 v2.6.0 起的 QQ 代码链路正常，"QQ 用不了"的典型原因是机器人 QQ 号与 NapCat 本地登录会话不一致，NapCat 一直停在扫码阶段而未真正登录。新版会监听 NapCat 的登录输出：检测到"快速登录失败 / 请扫描二维码"时，状态栏明确显示"等待扫码登录"并给出二维码图片路径，不再把"进程已启动"误当成"QQ 已就绪"；扫码登录成功或 OneBot 连接建立后自动恢复正常状态。
* **NapCat 运行库缺失兜底确认**：NapCat 官方截至 v4.18.19 仍未修复 Windows 包漏打包 crypto.dll/ssl.dll 的问题；启动器启动前仍会自动补齐（包内优先，其次从本机 QQ 安装目录复制），缺失时日志会给出明确提示。

### v2.6.0

* **26.1 / 26.1.2 原生直连完善**：修复机器人在 26.x 服务器"已自动接受资源包"后卡住不进服的问题——资源包响应改用兼容写法，服务器能正确收到确认并放行；同时适配 26.1 新增的多时钟时间包格式（clockUpdates），进服后不再因时间解析崩溃。配合已内置的 26.1 协议数据与配置阶段补包逻辑，机器人现在可以完整原生直连 26.1 / 26.1.2 服务器（协议 775），26.2 等更高版本仍走 ViaProxy 转换。

## 快速入门

### 第一步：环境准备

在开始创建机器人之前，请先进入**设置**页面完成基础环境的配置：
1. 下载并安装 **Node.js 运行时**。
2. 下载机器人运行所需的**基础包**。
3. （可选）如需接入 26.2 等新版本服务器，在「协议代理」中下载 **ViaProxy**，并确认本机有 Java 17+（26.1 / 26.1.2 原生直连，无需 ViaProxy）。
4. （推荐）直接点击一键下载把俩都装上 
### 第二步：创建机器人

环境准备就绪后，回到首页点击**创建机器人**。接下来请根据提示填写各项配置：

#### 1. 服务器配置
* **服务器地址 (MC_HOST)**：填写你要加入的服务器 IP（如果是你本地开的服务器，请填写 `localhost`）。
* **端口 (MC_PORT)**：服务器端口（默认通常为 `25565`）。
* **版本 (MC_VERSION)**：填写游戏版本。如果是代理/群组服务器，建议使用 `1.20.1` 并配合 ViaVersion 插件跨版本；26.1 / 26.1.2 原生直连；26.2 等新版本服务器请开启内置的 ViaProxy 代理。
* **用户名 (MC_USERNAME)**：给你的机器人起个名字（即它在游戏内的 ID）。
* **认证方式 (MC_AUTH_TYPE)**：正版账号选择 `microsoft`，离线服务器选择 `offline`。
* **登录密码 (MC_LOGIN_PASSWORD)**：选填。如果服务器有登录插件（如 AuthMe），填入密码后机器人会自动执行 `/l 密码` 进行登录。如果服务器没有密码请留空。
* **主人名称 (MC_OWNER_NAME)**：填写**你自己的游戏 ID**。机器人非常忠诚，它只会听从主人的指令。

#### 2. AI 配置
* **API Key (LLM_API_KEY) & API URL**：这是机器人的“大脑”，需要你自己购买并填写。
  * *提示：如果不了解如何获取，可以询问 AI。推荐使用 DeepSeek，价格比较便宜，性价比极高。如果暂时无法购买，也可以去寻找提供免费体验额度的 API。*
* **对话模式**：
  * 默认推荐使用 **whisper（私聊模式）**，这需要服务器安装支持 `/tell` 指令的插件。
  * 如果服务器没有安装相关插件，请选择 **public（公屏模式）**。

#### 3. 行为设置
在行为设置中，你可以开启机器人的各种“被动本能”：
* **登录自动传送**：已拆分为「接受 TPA」「自动登录」「死亡 back」三个开关——接受 TPA 会自动回应主人的传送请求（默认仅接受主人，可改为接受所有人）；自动登录会在进服后自动执行登录指令；死亡 back 会在死亡后自动回城。
* 你还可以根据需求勾选自动防御、自动进食、自动切换工具、自动丢弃垃圾等实用功能。

---

### 第三步：启动与交互

保存配置并创建后，启动机器人，它应该就能成功加入游戏了！
> ⚠️ **注意**：机器人加入游戏时可能会触发某些服务器的反作弊系统。如果被踢出，请检查服务器的反作弊设置或调整机器人的行为频率。

#### 如何给机器人下达指令？
* **游戏内指令**：如果使用的是 `whisper` 模式，请在游戏聊天框输入：
  ```text
  /tell <机器人名字> <你想让它做的事>
  ```
  *例如：`/tell MyBot 过来一下` 或 `/tell MyBot 帮我挖32个铁矿石`*
  （注意：机器人只听主人的话！）
* **控制台交互**：你在控制台输入的所有内容，都会被机器人直接发送到游戏中。

## 💡 机器人能做什么？（指令参考）
你的机器人接入了 AI 大脑，你可以直接用自然语言（大白话）给它下达指令！以下是一些常用的指令示例：

* **移动与跟随**：过来一下 / 跟着我 / 去坐标 100 64 -200 那里等我
* **采集与挖掘**：帮我挖32个铁矿石 / 去附近砍一组橡木原木 / 去附近帮我剪点羊毛
* **加工与合成**：帮我合成一个工作台并放下 / 帮我把身上的粗铁烧成32个铁锭
* **组合任务**：帮我挖3个铁矿，找点煤炭，然后烧成3个铁锭
* **建筑与破坏**：在你脚下放一个箱子 / 帮我用橡木木板把坐标 0 64 0 到 10 64 10 这片区域填平
* **农业与养殖**：帮我把这些种子种下去 / 用骨粉把附近的庄稼催熟一下 / 拿点小麦去喂一下附近的牛
* **战斗与安保**：去帮我杀几只僵尸 / 去揍那个叫 Steve 的玩家 / 在附近30格范围内巡逻一下
* **物品管理**：把你身上的东西都放进箱子里 / 从箱子里帮我拿一组钻石出来 / 扔给我一把剑

## 🛠️ 故障排除
在复杂的 Minecraft 世界中，机器人偶尔也会遇到一些小麻烦，你可以用以下指令控制它：
* **卡住不动了？** 机器人底层有“自动脱困”机制，通常稍微等待一下即可。
* **任务执行失败 / 卡循环？** 
  * 发送 `/tell <机器人名字> retry`：让机器人重新尝试当前任务。
  * 发送 `/tell <机器人名字> skip`：跳过当前任务，执行下一步。
* **想让它立刻停下？** 
  * 发送 `/tell <机器人名字> stop`：机器人会紧急刹车并清空当前的任务计划。
* **遇到无法解决的 Bug？**
  * 直接在面板关闭机器人然后重新开启即可，重启能解决 99% 的问题！
